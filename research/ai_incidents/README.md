# Investigation 1: AI incident analysis

This investigation selects clear articles about AI-related incidents, then aims
to organize reports of the same event into source-grounded dossiers. It uses the
existing incident-report dataset. It does not include the separate Netherlands
cybercrime investigation.

This folder is the study's navigation and methodology home. Historical executable
code and frozen source documents retain their original paths so that audit hashes,
request identities and reproducibility remain intact. Restricted articles,
identities, model replies, vectors and working records stay in protected storage
outside Git.

## Read in this order

1. [Methodology](METHODOLOGY.md): research question, selection, rationale,
   limitations and the four dossier processes.
2. [Validation ledger](VALIDATION.md): every identified relevant evaluation,
   its reported outcome and what it does or does not validate.
3. [Workflow and implementation map](WORKFLOW.md): existing components,
   historical entrypoints and work still needed.
4. [Shared dossier protocol](../shared/dossiers/METHODOLOGY.md): the reusable
   event definition and four processes, independent of AI or cybercrime relevance.
   Its [definition review](../shared/dossiers/DEFINITION_VALIDATION.md) records
   the 12 original and 50 additional invented boundary cases.
