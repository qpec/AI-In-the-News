# Auditability and enforcement

The optional [conversational RAG reader](CONVERSATIONAL_RAG.md) uses the same full runtime preflight and gateway boundary. Immutable evidence definitions link each question and answer to its original retrieval; explicit keyword searches create linked definitions. One submission allows at most one Codex account attempt, with durable manifests/intents/results, unknown-outcome protection and exact answer/search presentations. Read-only HTTP polling performs no research. This extension does not weaken integrity checks or accept model interpretations as findings.

## Enforced boundary

Every supported research command enters `Research.execute()`, whether launched by Codex, a terminal, a script or the Python API. The old source verifier also enters this runtime. There is no trusted `--no-audit` research mode. Hooks add lifecycle observations; disabling or omitting Codex does not disable the research journal.

The enforcement sequence is:

1. Validate objective, actor and credentials policy; verify workspace permissions, SQLite integrity, immutable protections, hash chain, artifacts, sources, stable passages and projections. Validate referenced versions and dataset/dossier consistency.
2. Persist session identity and intent: Git HEAD, hashes of working code/docs/config/skills/lockfile, Python/platform/SQLite/library identity, resolved research configuration, exact objective/actor/version bindings and preflight journal head.
3. Save the permitted operation input and durable intent before executing its handler. Method registration precedes dependent processing.
4. For model batches, persist the complete work-item manifest before the first call. Persist each exact request and attempt intent before invoking the provider. Persist permitted response bytes/structure, parsed result and validation before completing the attempt.
5. Commit review and acceptance only after a durable successful attempt, valid evidence and complete coverage. Unique claim/revision constraints and explicit corrections prevent duplicate acceptance.
6. Persist operation result and successful session end. Failures record their observable type when durable storage still works. A logging failure raises and stops the operation; it cannot be "handled" by accepting an unlogged output.

An attempt intent without completion remains an unknown outcome and blocks automatic resume for that task until an explicit resolution record. A crash after a valid result but before the outer operation completion can leave a usable durable result; recovery relies on manifest/task identities and persisted records, not on assuming the whole command failed or succeeded. Source imports and immutable record projections commit with their journal events in SQLite transactions. External artifact writes precede referencing commits, so an interrupted write may leave an unreferenced artifact; no automatic history deletion occurs.

There is one workspace writer at a time, enforced with an OS file lock. This foundation is a local, single-operator environment, not a concurrent multi-user service.

## Stored evidence and model observability

An explicitly selected provisional [query cutoff](SIMILARITY_TAG_AUDIT.md#provisional-operating-cutoff) uses a separate version-bound policy and appends yes/no/null source rows linked to the original scores. Policy, inclusive comparison, `threshold_validated: false`, deterministic decision origin and unreviewed status remain visible in SQL. A complete manifest precedes work; missing/interrupted processing stays explicit. The composed operation also freezes counts/overview/chart and exact presentation, without a new model call or acceptance. The calibrated path retains its passing held-out requirement; a provisional policy is not evidence of accuracy.

[Result presentations](RESULT_PRESENTATION.md) add immutable `result_presentation` SQL records with exact Markdown bytes/hash, original result IDs and version bindings, method, actor/session, destination, state and observed recording time. The mandatory assistant workflow captures and shows an overview after every search. `record_presentation` validates identity and fidelity, not the meaning of caller-supplied prose or its consistency with the results. Prepared content is distinct from caller-reported delivery; chat rendering and human reading are unobserved. Retrospective unknown message times stay null with a reason. Search APIs do not automatically publish chat messages, and a saved presentation alone does not prove delivery.

The standing user instruction also requires visible concrete results after every other research step, including judging, calibration, tagging, reviews and measurements, with no-run/zero/partial/failed states distinguished. The presentation allowlist includes `adaptive_cutoff_plan` and `adaptive_cutoff_result` alongside its nine search/retrieval kinds. The bounded cutoff workflow captures its exact presentation; arbitrary assessment, review and measurement kinds still require their own integration. Their operation audits do not prove exact chat-text capture. Report unsupported capture without fabricating a result link or a successful presentation record; automatic chat publication is not implemented.

The implemented [v3 adaptive cutoff](ADAPTIVE_LLM_CUTOFF.md) enters the shared gateway in one runtime operation. It verifies that the judge inclusion block exactly equals the original literal query/question embedding input, registers the retrospective criterion and method, saves sampling probabilities and round manifests, freezes the candidate before held-out dispatch, and retains weighted calculations and model-reference uncertainty. The [Codex CLI transport](CODEX_JUDGE_TRANSPORT.md) persists exact application-controlled stdin, argv, schema, worker rules and request/attempt intent before each dispatch, then saves visible responses before validation. At most four provider calls run concurrently with a single SQLite writer. Authorization-key counters cap observable article attempts/unique articles across child plans and resume; unknown outcomes remain spent and block automatic re-dispatch of that source, including a changed task key. Technical failures preserve a partial result instead of automatically filling reserve slots. Only `passed_model_reference` appends new provisional tags, always with `human_validated: false`.

[Embedding-based query tags](SIMILARITY_TAG_AUDIT.md) add an immutable `article_query_result` SQL record for every article in a completed run. Each row retains exact query/question, score, yes/no/null relevance answer, cutoff/calibration, source/vector versions, matching evidence, coverage, actor/times and links to the shared query request and session audit. Full-corpus manifests precede scoring; interrupted runs expose expected/logged/pending counts. Threshold application appends new rows linked to the original scores. The audited SQL reader retains its SELECT and parameters. Shared query token usage is explicitly distinguished from zero per-article inference usage. These records remain provisional and do not enter dossier acceptance or measurement tables.

| Information | How it is preserved |
| --- | --- |
| Original sources | Permitted original bytes for stored-response imports; content hash, normalized immutable source, provider fields, actual retrieval metadata |
| Stable evidence | Source-version hash, paragraph ID/hash, Unicode character offsets, exact quote and source offsets |
| Research methods | Immutable question/protocol/selection/dossier-definition/codebook/prompt/profile/policy/evaluation records, amendments and branch names |
| Request | Exact application-controlled instructions, boundary instructions, full supplied evidence, task type, parameters, schema, provider/model identity and input versions |
| Attempt | Stable task key, attempt UUID/number, prior manifest, local start/end times, observable errors/retries and status |
| Response | Permitted provider response object/raw payload, returned provider/model/request ID/usage when available; parsed result and validation |
| Interpretation/review | Model interpretation separate from source claims; exact citations, review decision/rationale/identity or policy, accepted immutable revision |
| Analysis | Frozen SQL/parameters/rows, versions, frame/included IDs, denominator, exclusions, missingness, uncertainty and calculation digest |
| Visualization | PNG artifact and immutable link to its table/digest/calculation |
| Codex hooks | Allowlisted event/session/turn/tool-use/tool-name/model metadata, separate protected lifecycle journal |

Unavailable request IDs, usage or model metadata remain null. Local timestamps are observations, not provider clock times. Error messages are not stored verbatim because provider exception text can expose secrets; types and safe validation reason codes are retained. Hidden reasoning, provider internals and a model's actual attention are not observable and are never fabricated. Original payload fidelity is conditional on retention permission; prohibited payloads must not be sent through an adapter that cannot meet the declared policy.

Credential fields and recognizable secret formats are rejected, rather than silently redacting and misrepresenting a request as exact. No environment dump, auth files, transcripts or provider credentials are logged. Pattern detection cannot recognize every possible secret: keep credentials outside research payloads. The [OpenAI embedding transport](OPENAI_EMBEDDINGS.md) reads its key from the process environment for a plan-authorized request, only sends to the fixed HTTPS endpoint, and rejects redirects. The recorded wire body excludes authentication headers; the actual key is never an audit input.

The registered offline pilot preparation handles a credential-flagged selected archive row by retaining only its already-validated locator metadata and hash as a metadata-only source. It persists no matched value, raw row, provider record or text from that row. A separate quarantine manifest preserves its selected membership and unprocessed status; the record is not silently replaced. This is a versioned retention exclusion, not redaction of a supposedly exact payload or a determination that the source contains a real credential. The legacy archive is not changed.

## Storage and local tamper detection

Working data live outside Git. New Windows roots remove inherited broad grants and use the current user's SID plus SYSTEM; local Administrators/owner rights can remain. Preflight rejects broad ACLs and links/junctions. POSIX roots require owner-only permissions. Artifact names are SHA-256 of their bytes. Files are flushed and fsynced; SQLite uses WAL, `synchronous=FULL`, foreign keys and append-only UPDATE/DELETE triggers for evidence/audit tables. Schema changes are not automatically repaired.

The journal is the append-only `events` table in `research.sqlite3`, linked by SHA-256 over each canonical event and its previous hash. Immutable projections reference their creating event and content-addressed artifact. Preflight verifies journal continuity, required artifacts, source/paragraph integrity and index coverage; SQL cannot ordinarily update or delete historical records. The FTS index is derived and checked against evidence.

Preflight still checks the complete store on every invocation. Record projection bytes are hashed against their artifact reference, and the final streaming sweep checks every actual artifact's full contents and permissions, including unreferenced files and shared raw imports. This avoids reading each record artifact twice without replacing content checks with file metadata. Verified raw imports are parsed once; each source must match its exact canonical raw entry and source hash. Indexed ordered source and passage cursors check exact text, Unicode offsets, hashes, segmentation and complete per-source coverage without repeating full source JSON in every paragraph row. Windows security API bindings are reused, but ACL values and permission decisions are always read afresh. No verification outcome is cached across calls, and durable session/intent/result writes, unknown-attempt reconstruction and all failure behavior remain enforced.

These measures detect accidental corruption and many partial modifications. **They do not establish adversarial tamper-proof storage.** An administrator or owner who controls code, database and artifacts can remove triggers, rewrite an entire chain, falsify identities or restore a consistent earlier backup. No external checkpoint, trusted clock, signature service, WORM store, remote attestation or rollback detector is installed. Local ACLs do not encrypt data or protect it from the same logged-in user, malware, administrators, backups or synchronization software. Filesystem/hardware power-loss guarantees and Windows directory metadata durability are platform-dependent. For stronger assurance, add an independently controlled append-only checkpoint/backup service; do not present the current hash chain as proof against its owner.

## Codex project integration

`.codex/config.toml` uses supported project-local `features.hooks`, `project_doc_max_bytes` and inline command hooks for SessionStart, PreToolUse, PostToolUse and Stop. `.agents/skills/` supplies reusable research operations, review and measurement workflows. `AGENTS.md` contains mandatory rules and references this document and the research protocol.

The hooks invoke `uv run --offline --frozen python -m newsresearch.hooks`. Run `uv sync --frozen` first. `uv` locates the project from a repository subdirectory. Hook payloads are reduced to a small metadata allowlist before entering the runtime. The hook journal defaults to a sibling `codex-hooks` protected directory so a long research process cannot block lifecycle logging on the research workspace lock. Concurrent supplementary hooks retry only the exact constructor workspace-lock contention error for at most 15 seconds; other audit/storage failures still deny immediately, and execution failures are never retried by that helper. Tests can override the hook store with process-local `NEWSRESEARCH_HOOK_WORKSPACE`.

Project configuration requires a trusted project. Local command hooks also require Codex's explicit hash-based review in `/hooks`; project trust alone does not approve them. This implementation does not write global settings or approve its own hooks. On an observed audit failure the PreToolUse handler returns a supported explicit denial. A callback that never starts, times out, emits invalid output or is unsupported by the current host can fail open, so the runtime remains mandatory. SessionEnd is not configured because its short timeout is unsuitable for durable full preflight. Existing sessions may require a new project session/reload to discover configuration and skills.

Compatibility is verified against the installed CLI, not inferred from documentation alone; see [VERIFICATION](VERIFICATION.md) for the exact version and observed discovery/trust state. No model turn is needed to inspect configuration, hooks and skills. The same hooks may not be available in a cloud-orchestrated host even when tools execute locally.

Official references: [Codex hooks](https://learn.chatgpt.com/docs/hooks), [advanced configuration](https://developers.openai.com/codex/config-advanced/), [configuration reference](https://developers.openai.com/codex/config-reference/), [skills](https://developers.openai.com/codex/skills).

## Coverage limitations

- The boundary covers the shipped CLI/API and providers routed through its gateway. A local user can run arbitrary Python, SQL, shell tools, network clients or direct provider SDKs outside it. Neither Python encapsulation nor Codex instructions are an OS sandbox. Such activity is outside the audit; it must not be incorporated as accepted research without recorded provenance.
- Codex's own conversational inference, internal system/developer instructions, hidden reasoning, hosted web/image tools, arbitrary external browsing and human work are not gateway-observed. The dedicated Codex CLI article-judge transport captures application-controlled packets and visible responses only. Its configured model alias is pinned, but actual model/request identity, provider drift, usage and billing may remain unavailable; unavailable is never zero. Do not claim that all Codex token usage or thought is captured. Substantive dossier judgements still have only an offline mock. The OpenAI embedding transport produces retrieval representations, not judgements.
- Hooks omit tool inputs/outputs, prompts, transcript content and environment variables by design. Hosted tools can bypass local hooks; `write_stdin` continuations do not receive a new PreToolUse check; some specialized paths opt out. This is lifecycle coverage, not a transcript or provider audit.
- Failures before argument parsing, workspace availability, preflight or a successful first durable write cannot be recorded in that failed workspace. The CLI stops and reports an error. A missing session-end record indicates interruption, not proof that no work occurred.
- Inspect/search logs show passages returned, not what a person read. Model inspection is self-declared. Quote matching does not validate truth, entailment, bias, dossier quality or scientific usefulness.
- Export allowlists and minimum cells reduce accidental leakage but do not implement differential privacy, repeated-query controls, all disclosure-risk checks or publication-rights review. CLI stdout is private when it contains evidence; shell redirection and external copying are outside export enforcement.
- The older private Git data archive remains preserved. It predates the outside-Git policy and has not been purged from history. Future restricted working data use the protected store.

## Unfinished integrations

The separate [Dutch cyber-news pilot](NL_CYBER_SEARCH_PILOT.md) adds a narrowly
authorized `newsapi_probe` operation through `Research.execute()`, with immutable
pre-dispatch reservations, ten-dispatch/200-token conservative budgeting, protected
responses, no automatic retries and exact supported presentations. This does not
enable general `collect` or pagination. Its actual historical checks reported no
archive use; three-year coverage remains unestablished. One early non-JSON failure
has an unresolved reserved outcome without captured response bytes. Later adapter
versions retain non-JSON failures. See the study method for observed counts and
billing limitations.

The bounded adapter currently requires unchanged approval content on resume. A code-only review identified that changing approval metadata (including expiry) can change the plan identity used by the holdout-open lookup. Do not amend an existing workflow approval or treat its held-out articles as newly sealed; immutable approval-lineage enforcement is still required before that path is supported. The actual 2026-10-15 resume preserved identical approval content and never opened its held-out set. See [VERIFICATION](VERIFICATION.md) for the partial execution outcome.

The [adaptive cutoff v3 adapter](ADAPTIVE_LLM_CUTOFF.md) and its [Codex CLI gateway transport](CODEX_JUDGE_TRANSPORT.md) are implemented for the exact existing literal-query criterion. Expanded semantic criteria still require a separate new-query embedding/rescoring plan. Proven operating-system tool/filesystem isolation, guarantees over unobserved internal requests/generation/billing, and independent human validation remain unfinished. Fresh processes, read-only CLI and no-tools instructions do not prove isolation. A hard provider token/cost cap cannot be claimed without enforcement. The corpus-wide Responses adapter must not silently replace the selected Codex route. Registration and software tests neither execute judging nor turn model labels into human gold; actual run status belongs in verification and the visible result presentation.

The [query-tagging adapter](QUERY_TAGGING.md) now implements a substantive OpenAI Responses transport for provisional article relevance, separate from the still-mocked dossier provider. It retains the complete article/segment manifest, exact application-controlled request body, observed raw response and HTTP/model/usage metadata, citation validation, missingness, cost reservations, reviews and calibration provenance. Default operation remains offline and each paid tag run needs its own concrete plan-bound authorization. Synthetic HTTP tests do not establish service access, calibrated scientific accuracy or independent human review. Article tag records cannot enter accepted dossier measurements through this adapter.

Live NewsAPI.ai/Event Registry pagination, rate limits, collection authorization and credentials; substantive dossier-model transports and general payload-retention negotiation; useful learned event grouping; authenticated multi-user review; independent human gold labels and scientific evaluation; sampling-weighted population estimators; secure off-device backups/checkpoints and encryption management; general-purpose statistical/visualization plugins; and publication-grade privacy controls remain unfinished. `collect` and substantive live dossier providers fail closed. The OpenAI embedding adapter is guarded by offline defaults and concrete run permission; offline tests do not establish real service access or scientific quality. The offline ingestion, audit, grouping proposals, lexical retrieval, mock processing, review, dossier counts, charting, replay and safe aggregate projection are working implementations.

Local [vector candidate retrieval](LOCAL_CANDIDATE_SEARCH.md) now runs inside `Research.execute()` using already-audited embeddings. Index binaries, normalized vectors, exact source/chunk mappings and candidate artifacts are protected and journal-anchored. Large binaries use streaming hash verification, and index serialization uses a fsynced content-addressed file copy. The saved index's integrity does not establish semantic retrieval quality. Exact-search comparison measures numerical neighbors only; independent event-level retrieval evaluation remains unfinished.
