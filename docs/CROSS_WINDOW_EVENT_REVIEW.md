# Complete-source review between seven-day event groups

This exploratory second tier continues the user's separate cross-window linking
request. The current guarded seven-day groups remain unchanged. The older strict
provider-ID tier is preserved; its zero candidates do not establish absence of
long-span same-event reporting. This method does not relax that frozen tier.

## Registered offline preparation

Enter `prepare_cross_window_event_review` through `Research.execute()` using
`scripts/prepare_cross_window_event_review.py`. Register protocol, question,
selection, dossier definition, prompt, codebook, analysis profile and model
configuration before processing. Bind the existing seven-day policy/result,
saved date-free feature table, original pilot, source versions and code hashes.
Perform full preflight and preserve durable intent/results. Store source bodies,
passages, instructions and model-ready packets only in protected storage.

1. Consider all existing groups, including singletons. A saved passing
   cross-article edge nominates a group pair. Retain unions spanning more than
   seven publication days. Shared provider event IDs are not mandatory.
2. Require every cross-group article pair to have complete, finite scores passing
   all five unchanged cosine gates, ignoring only the time gate. Preserve
   missing rows, failed/pending/unknown processing, invalid features and below-gate
   scores separately. Missing evidence never means different events. A score
   rank or this gate is not a calibrated same-event probability.
3. Preserve the original body-disjoint sealed validation fold. Source packets may
   include only articles assigned to the original development body fold;
   duplicates inherit their body's existing fold. No new split or held-out
   judgments are created. The resulting queue cannot estimate population
   precision, recall or independent quality.
4. For bounded semantic review, require two distinct URL domains and stored-body
   hashes, and at most six articles in a union. These are priority/diversity
   screens, not proof of independent reporting or correct source extraction.
   Prioritize unions involving an existing multi-article group, then smaller
   unions, weakest normalized five-feature margin, and stable group IDs. Select
   at most ten disjoint group pairs and 36 unique article-pair requests, admitting
   a candidate only if its entire task set fits. Record every exclusion and
   selection bias, candidate type and publication-span band.
5. Prepare **every unordered article pair in the entire union**, including pairs
   within existing groups. Existing groups are not semantically verified merely
   because they passed the seven-day numerical rule. Representative-only checks
   and transitive AB/BC inference cannot approve AC.
6. Freeze the full frame and queue before revalidating the 54 existing development
   model references. Preserve overlaps and conflicts without removing them to
   manufacture a successful evaluation. Old labels are comparison references;
   no identical-new-version model cache result is fabricated.
7. Build requests using the existing full-source event-pair contract. Preserve
   exact permitted bodies, all stable passages, source hashes, instructions and
   schema; revalidate complete coverage. Pin the original Codex model and verify
   its executable hash. Prepare exact CLI inputs with the existing 500,000-byte
   input/2,000,000-byte output acceptance limits and 180-second timeout, without
   starting a process. Preserve source and transport preparation failures.
8. Preserve the original workflow's cumulative 90 primary/10 retry allocation,
   100-attempt/200-article-exposure ceiling, including invalid/unknown attempts.
   At preparation time, 55 spent attempts would leave 36 primary and nine retry
   attempts. Read actual durable totals; do not assume that snapshot at dispatch.
   This new exploratory branch does not repurpose the original held-out test as
   validation. Fresh concrete authorization must bind this queue and any new
   use of the remaining allocation; the original approval expired. No model
   execution permission follows from offline preparation.
9. Freeze packets before exports so audit-failure recovery reuses exact input and
   worker manifests. Record the exact results overview linked to immutable IDs
   before presenting it. Prepared presentation is not verified UI delivery.

## Required next semantic step

Use Codex article judges through the existing shared audited gateway, never
native chat inference or an API substitute. Recheck live authorization expiry,
budget, configuration, code and evidence bindings before dispatch. Reserve every
attempt durably and account for retries and unknowns. No execution is performed
by this preparation operation.

The unchanged contract distinguishes same focal event, different event and
uncertain, with source-backed actors, action, event date and location. It keeps
publication dates separate from event dates, and different developments separate
from the same event. All pairs in a union must support the same focal event;
uncertain, missing or failed judgments cannot approve a merge. Even unanimous
model support is provisional, with no calibrated extreme-probability claim.
Acceptance and actual membership changes require the project's identified
reviewer or registered automatic acceptance policy, with merge lineage.
