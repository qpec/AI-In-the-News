## Implemented offline proposal mechanism

Method `seven-day-working-choice-and-strong-cross-window-proposals-v1`, entered
through `Research.execute()` by `scripts/propose_cross_window_group_links.py`.
Register the method and working policy before execution. Complete preflight,
durable intent/results, protected artifacts and session provenance are mandatory.

1. Bind the completed actual-window comparison, original guarded working frame,
   unchanged five-feature rule, saved date-free scores and provider snapshot by
   exact versions and code hashes. Do not recompute embeddings or call models.
2. Classify each current multi-article group as fully anchored, partial,
   conflicting or missing provider IDs. A strong pair requires **every member in
   both groups** to have the same exact nonempty Event Registry eventUri. Partial
   anchoring cannot enter this tier. Preserve every group classification.
3. Consider fully anchored group pairs sharing that URI whose combined publication
   span exceeds seven days. Require at least two distinct URL hostnames and two
   nonempty exact-body hashes across the union. These are diversity signals, not
   proof of independent reporting or correct source extraction.
4. Require every cross-group article pair to have completed, finite scores passing
   all five original cosine thresholds with only the time gate ignored. Missing
   rows, failed/pending/unknown processing, invalid/missing features, below-cutoff
   scores and diversity failures remain separate reasons. Lack of a qualified
   link never establishes different events. Candidate minima are partial unless
   every expected comparison is completed; only fully qualified pairs have
   complete minima.
5. Build complete-link groups of old groups from qualified pair links. AB and BC
   cannot establish AC. Preserve qualified bridges and every coarse candidate's
   identities, member/ID coverage, diversity, gap, cross-pair counts, weakest
   features and exclusions. This produces unjudged proposals only.
6. Freeze all proposals before revalidating/reusing every original development
   model reference with its source versions, probability and weight. Simulate
   co-memberships for diagnostics only; compare baseline and raw proposals.
   Preserve known-conflict quarantine separately. Filtering against these labels
   cannot be reported as independent successful validation. Uncertain references
   remain distinct; missing processing never becomes a negative.
7. Keep active seven-day memberships unchanged. Actual cross-window merging
   requires reviewed event facts—actors, action, place and event date—with cited
   evidence. Provider agreement and cosine are not calibrated probabilities.
   Native Codex reasoning is not an audited article judge; no new paid/model run
   is authorized or launched by this offline step.
8. Save exact private frames, proposals, exclusions, reference effects and count
   SQL/parameters. Record the exact result presentation before showing it. Prepared
   output does not establish verified UI delivery or human reading.

This first tier deliberately omits singletons and groups without full provider
anchors. It is not a complete event-coreference system, nor a claim that every
high-likelihood match has been recovered. Future unanchored candidates need an
explicit evidence-based event-coreference/review workflow and its own concrete
model authorization before judging.
