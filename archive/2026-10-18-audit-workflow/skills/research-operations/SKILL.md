# Audited research operations

Read root `AGENTS.md`, [protocol](../../../docs/RESEARCH_PROTOCOL.md), and [auditability](../../../docs/AUDITABILITY.md).

Within the user's authorized scope, proactively complete reversible implementation, validation and feasible method execution; do not stop at a specification or plan when execution can proceed. Report a genuine blocker and partial results explicitly. This does not authorize separate paid API work, collection, budget expansion or audit bypass.

1. Establish the objective, actor, protected workspace and exact method/version bindings. Use `uv run --frozen newsresearch` or `Research.execute()`; both enforce the same preflight and audit. Read-only research is audited too.
2. Register the method, selection and research question before execution. Preserve amendments with `supersedes`, a reason and an explicit exploratory branch where appropriate. Keep request JSON containing sources outside Git.
3. Import permitted saved Event Registry responses using `import_newsapi`. Record the actual retrieval time and parameters; do not invent unavailable history. Never run live collection or paid inference without concrete authorization and an implemented transport.
4. Use `propose_groups` only after registering its deterministic method; review candidate memberships before saving a dossier version. Keep uncertain assignments, duplicate reporting and merge/split lineage.
5. Use `search` then `inspect` with dataset/version bindings. Report retrieved coverage, not corpus prevalence. Call `batch` only for the selected dossier IDs and question. All classification, extraction, grouping, summarization and retrieval judgements use the shared gateway.
6. Re-submit the same manifest inputs to resume. Cache reuse is explicit and version dependent. On an unresolved attempt, preserve its unknown outcome and record `resolve_attempt` with the operator's reason before retrying. Never replace a failed item with a negative label.
7. Hand provisional results to `research-review`. Use `trace` for accepted findings and `replay` for stored outputs without fresh inference. Always show concrete available results in the same chat after every research step, including judging, calibration, tagging, reviews and measurements. Include scope, coverage, uncertainty, missing/failed/pending processing and available examples/evidence; for relevance include cutoff and yes/no/null totals. Explicitly distinguish no run, zero results, partial processing, method design and software tests. A commit or file path alone is insufficient. Capture exact presentations for supported result kinds; identify unsupported capture without fabricating references or claiming logging. Do not start new research just to fill a status update.
8. After every search, show its results without a follow-up request: exact query, scope, coverage/missingness, ranked matches with available scores/source links and limitations, including zero or incomplete results. For exhaustive query scores, first use `article_query_overview` with the original run bindings. Save the exact Markdown with `record_presentation` and then show that recorded text; a saved file or completion notice alone is insufficient. This is a mandatory agent workflow, not automatic chat rendering by the CLI. Retrospective delivery is caller-reported; unknown message times remain null with a reason. See [the presentation contract](../../../docs/RESULT_PRESENTATION.md).
9. Query relevance also requires a cutoff and yes/no counts. Use `similarity_apply` only with its passing calibration. For an explicitly selected unvalidated operating cutoff, use the separate `similarity_provisional_apply` with original score completion ID, threshold and rationale; it appends individual provisional decisions, builds the overview and captures its exact presentation in one audited operation. Show the returned presentation unchanged. Missing scores stay null. Arrange independent human calibration and held-out validation before claiming accuracy; no native chat gold labels or fabricated evaluation.
10. For bounded calibration, read [ADAPTIVE_LLM_CUTOFF](../../../docs/ADAPTIVE_LLM_CUTOFF.md), its v3 machine-readable protocol and the [Codex-agent CLI transport contract](../../../docs/CODEX_JUDGE_TRANSPORT.md). The implemented `adaptive_cutoff` operation runs through `Research.execute()` and the shared gateway, with a fresh ephemeral process/protected cwd per article, pinned `codex_model`, existing ChatGPT account authentication and no API-key/Responses fallback. The literal variant verifies and reuses exactly the original query/question embedding UTF-8, registered retrospectively without expanded criteria; new semantic criteria still require a new query embedding/scorerun. Persist/reserve before dispatch, preserve score-blind evidence, full-support marginal sampling probabilities, frozen candidate before held-out judging and authorization-wide 100/200 attempt caps. At most four provider workers share a single SQLite writer. Unknown outcomes remain spent and block automatic re-dispatch of that source even with changed task identity; technical failures stop partial with no automatic reserve refill. Explicit same-version cache reuse is recorded. Only `passed_model_reference` applies new provisional tags, always `human_validated: false`; show an inconclusive candidate without applying it. No-tools/read-only/fresh-process controls do not prove filesystem isolation; unavailable usage is not zero. Show the returned `adaptive_cutoff_plan`/`adaptive_cutoff_result` presentation unchanged. Do not launch a corpus-wide paid plan to emulate this workflow.

For saved embeddings, use `build_vector_index` with the exact original plan/run/context, then `vector_search`, `evaluate_vector_index` and `inspect_candidates` with the returned index context. Follow [the local retrieval contract](../../../docs/LOCAL_CANDIDATE_SEARCH.md). Candidate and exact-neighbor diagnostic counts are technical workload/coverage, not event or dossier findings. Preserve unprocessed text, separate provider-ID signals and explicit per-article reuse. No API key or online setting is needed.

Native Codex reasoning, web tools and arbitrary SDK calls are not audited model transports. Do not use them for unrecorded research inference. Stop on audit failures; do not repair history by editing SQLite or artifacts.
